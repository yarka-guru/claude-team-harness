- Red CI on your PR is yours until proven otherwise: read the failing step and compare with the latest run on the default branch before calling it pre-existing (a "fails on main too" job turned out to be a runner image change, fixed in one commit).
- Write PR bodies and drafts from the final commit: every reason, step and scope comes from the diff or a command output, and the text is rewritten after each code change (a large share of reviewer FAILs are wrong facts in PR bodies and chat drafts, not code).
- Local tests never write into the real home directory: throwaway `HOME`, `GIT_CONFIG_NOSYSTEM=1` and an empty credential helper for git, dev secret stores that do not save a token file, and no service started from a checkout inside the workspace (a dev server overwrote the user's token file, and a repro left fake credentials in the OS keychain that git kept sending).
- A script the user runs on prod cleans up in a `trap` on every exit and branches on observed state (what is deployed, PR state), not a step counter, so a re-run after any failure is safe and never repeats a pre-switch step after the switch (missing cleanup and resume paths cost three review rounds).
- Never read a credential value yourself, not even into an unprinted script variable: a check that needs a live secret is a subcommand of the script the user runs, and it prints only the result (an engineer read a token from a cluster secret to probe an API, outside the brief).
- Every PR, ticket, run or file named in an outward draft carries its URL at first mention; check this before handing the draft to the reviewer (missing links alone cost whole review rounds).
- An absolute in outward text ("the only way", "every token", "public", "never") is a separate fact: show the evidence for the absolute itself or write the narrower statement the evidence supports (overstated scope is the most common reason a fact-check round fails).
- The fact-check gate hashes the text the call sends, not your draft file: for a ticket that is summary plus description without a title label, so after a block the reviewer records the pass on the hook's saved copy named in the block message.
- Text for a public repo (PR body, commit, issue) holds nothing about the author's machine, network or accounts: a test that fails only locally is left out or described by its CI result.
- A script the user runs that prints more than one value says next to each value what to do with it (which field to paste it into, or "compare only, do not paste") and prints the web-form choices on screen.
- A report gives a separate verdict for every finding named in the card title; a finding you did not check is listed as "not checked".
